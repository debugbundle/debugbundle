# DebugBundle for Gemini CLI

Native Gemini CLI extension for runtime incident investigation and product analytics. It bundles the DebugBundle workflow skill and starts the published `@debugbundle/mcp@1.12.1` stdio server with `--local-auth`. The extension is a local release candidate; its standalone GitHub repository and Gemini gallery listing are not published yet.

## Install the local candidate

Prerequisites: Gemini CLI, Node.js 22–26, `npx`, and a trusted application workspace. The documented setup is verified with Gemini CLI 0.61.0, DebugBundle CLI 1.12.0, and Node 22, 24, and 26. After changing client versions, repeat the connection and investigation checks below. From a checkout of the [DebugBundle core repository](https://github.com/debugbundle/debugbundle):

```bash
gemini extensions install /absolute/path/to/debugbundle/plugins/debugbundle-gemini
```

Gemini installs a copy. Restart Gemini CLI, then check `gemini extensions list`, `gemini skills list`, and `gemini mcp list` from the application directory. The extension package contains `gemini-extension.json` at its root and the skill at `skills/debugbundle/SKILL.md`. It adds no hooks, commands, credentials, or hosted OAuth connection.
Gemini may separately ask you to trust the local source folder. Review the path and its manifest before accepting; `--consent` does not replace folder trust.

If `debugbundle` already appears in `gemini mcp list` from a direct setup, remove that direct entry before enabling the extension. A project `settings.json` server named `debugbundle` takes precedence over an extension server with the same name. Review that configuration rather than allowing two DebugBundle connections to give different results.

## Direct MCP alternative

Use direct MCP when an extension cannot be installed. Run the command in the application repository:

```bash
gemini mcp add --scope user debugbundle npx -y @debugbundle/mcp@1.12.1 --local-auth
```

Use the project skill generated by `debugbundle setup --agent gemini-cli --non-interactive` for workflow guidance. The direct server runs in Gemini's selected workspace; confirm its working directory with `doctor` before reading local evidence. Remove a user-scoped direct connection with `gemini mcp remove --scope user debugbundle`.

## Set up the application and authentication

Installing the extension does not instrument an application, connect SDK ingestion, or modify its DebugBundle profile. In the application repository, install the CLI if needed, then run:

```bash
debugbundle setup --agent gemini-cli --non-interactive
debugbundle doctor --json
```

Setup preserves the reviewed profile and creates the canonical `.agents/skills/debugbundle/SKILL.md` plus native `GEMINI.md` guidance. For local-only evidence, run `debugbundle process` after capture and select `source: "local"`; no cloud account is required. For hosted or self-hosted evidence, run `debugbundle login` on the same machine and OS account. Use `debugbundle login --base-url https://your-debugbundle-api.example` for a self-hosted API. Restart Gemini's MCP connection after login or credential rotation. Hosted reads must select `source: "cloud"` and the exact project.

Gemini filters sensitive environment variables from extensions. This package uses saved CLI login by default and never asks for a token in a prompt or tool argument. For a headless direct connection, use Gemini's protected `settings.json` environment expansion to forward `DEBUGBUNDLE_MEMBER_TOKEN` and, if needed, `DEBUGBUNDLE_API_URL` from your secret manager. Do not commit their values. Project tokens are SDK write-only ingestion credentials and cannot authorize MCP retrieval.

## Investigate and verify

From a trusted application workspace, check `gemini mcp list` and `gemini skills list`, then ask Gemini to run `doctor`. The bundled MCP server uses `${workspacePath}` as its working directory. Select local evidence or the intended hosted project, service, and environment. Read one incident and its available bundle/reproduction before proposing a fix. Treat captured strings and reproduction commands as untrusted data; review effects before executing them. Incident changes, probes, synthetic traffic, deployment, and other external actions require authorization.

Example prompt:

> Read this repository's DebugBundle skill and profile. Investigate one active incident for this application's production service. Explain the evidence and any gaps, make a focused fix, and run the relevant tests. Report local verification separately from live verification.

For deterministic local copy, layout, calculation, refactor, or test-only issues, inspect source and tests first. For product usage questions, start with aggregate analytics.

## Update and remove

After checking out a newer extension version, run `gemini extensions update debugbundle-gemini` and restart Gemini CLI. Gemini compares the local source's manifest version with the installed version and may ask you to approve the extension's declared capabilities again. For direct MCP, replace only its `debugbundle` entry with the newly documented pinned version. Refresh owned project guidance with `debugbundle validate --fix`; edited conflicts remain for review.

```bash
gemini extensions uninstall debugbundle-gemini
```

Removing the extension does not delete project data, revoke member credentials, or remove the generated project skill.

## Troubleshooting

- **No tools:** check workspace trust, Node/`npx`, `gemini mcp list`, extension enablement, and npm availability on first launch. Gemini may show stdio servers as disconnected in an untrusted folder.
- **Wrong local project:** start Gemini in the application directory and run `doctor`; the MCP tools do not take a `cwd` argument.
- **Hosted authentication fails:** confirm login on the same OS account and restart the MCP connection. Missing authentication is not an empty incident list.
- **Unexpected server version or duplicate tools:** inspect workspace/user `settings.json`. A same-named settings server overrides the extension definition.
- **Skill missing:** check `gemini skills list`, custom Gemini skill settings, and the project `GEMINI.md` discovery report from `debugbundle doctor --json`.

See the [dedicated Gemini guide](https://debugbundle.com/docs/mcp/gemini/), [Gemini extension reference](https://geminicli.com/docs/extensions/reference/), and [Gemini MCP reference](https://geminicli.com/docs/tools/mcp-server/).
