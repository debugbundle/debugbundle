# Product Specification — DebugBundle

Version: v1
Last updated: 2026-03-09

---

## 1. Product Definition

DebugBundle is an **AI-agent-first runtime debugging platform** that captures production failures, preserves deterministic debugging context, and exposes that context through **CLI + API + MCP** so developers and AI agents can investigate incidents, reproduce them, propose fixes, and open pull requests.

**One-sentence definition:** DebugBundle turns production failures into structured debugging bundles that developers and AI agents can use to reproduce and fix issues quickly.

---

## 2. Product Category

**Production Debugging Infrastructure**

DebugBundle is NOT:

- A generic dashboard-heavy observability suite
- A video session replay platform
- An AI chatbot that only summarizes logs
- A replacement for local coding agents
- A monitoring or alerting dashboard

---

## 3. Core Thesis

> The primary operator of debugging infrastructure will increasingly be the local or hosted AI coding agent.

The product is designed for that reality from day one. The long-term customer is not just the human developer — it is the AI agent acting on their behalf.

---

## 4. Core Product Artifact

The most important object in the system is the **Debug Bundle**.

A Debug Bundle is a structured, versioned, privacy-aware, deterministic package of incident debugging context. The platform succeeds when a bundle provides enough information for an AI agent to act on an incident without additional manual investigation.

### Bundle Types

- **Failure Bundle** (core) — triggered by exceptions, crashes, fatal errors, failed requests
- **Improvement Bundle** (all tiers) — triggered by warnings, deprecations, slow queries, retry loops, performance bottlenecks

### Improvement Bundle Tier Model

| Dimension | Free / Solo (Local Agent) | Team (Cloud) |
|---|---|---|
| Who runs analysis | User’s own agent + their LLM tokens | DebugBundle cloud, automated |
| When it runs | On-demand — user/agent invokes `debugbundle analyze` | Continuously — every ingested event |
| What triggers it | User invokes CLI/MCP | Automatic: `improvement_bundle.created` webhook fires |
| Historical context | Current codebase + local bundles only | Full incident history, cross-deploy trends, regression detection |
| Cost to DebugBundle | Zero — user pays own LLM costs | Our compute |
| Profile depth | Same profile.json | Same profile.json, enriched with production telemetry patterns |

The skill layer (`.agents/skills/debugbundle/assets/schemas/`) ships open-source analysis recipes (structured input/output schemas + few-shot examples) that any AI agent can follow. The same bundle schema is used whether generated by cloud or by a local agent.

## 5. Canonical Primitives

The platform is built around three canonical primitives that define the system's data model and integration surface:

| Primitive | Description | Schema Location |
|-----------|-------------|-----------------|
| **bundle** | Deterministic debugging artifact — the core product output | `/contracts/data-schemas.md` Section 1 |
| **incident** | Fingerprint-grouped container for related events — the grouping unit | `/contracts/data-schemas.md` Section 5.8 |
| **profile.json** | Project-level configuration and agent guidance | `/contracts/data-schemas.md` Section 7 |

Every feature, API, CLI command, webhook, and MCP tool operates on one or more of these primitives. New capabilities must map to these primitives rather than introducing parallel concepts.

**Probes** are a cross-cutting always-on diagnostic mechanism (not a new primitive). The `probe()` SDK method buffers structured data in per-label ring buffers; when an error occurs, all probe buffers flush alongside the error and attach to bundles as `context.probe_data[]` (correlated by `trace_id` or time window). This always-on behavior is available on **all tiers** — zero activation needed, data is there on the first error. **Paid-tier remote activation** (Solo+) allows agents to activate probes for independent shipping (without waiting for errors) via API/CLI/MCP, with backend SDKs polling `GET /v1/sdk/config` (CDN-edge-cached) and browser SDKs using zero-polling (session-start check + ingestion-response piggybacking). Heavy probes (expensive diagnostics) are dormant in always-on mode and only fire when remotely activated (paid tiers).

## 6. Product Shape

The MVP product consists of:

| Layer | Priority | Description |
|-------|----------|-------------|
| SDK | 1 | Runtime signal capture (Node.js backend + browser) |
| CLI | 2 | Primary human/agent interface |
| API | 3 | Cloud ingestion + storage + bundle generation + probe activation |
| MCP | 4 | Agent integration interface (thin adapter) |
| Web App | 5 | Minimal: auth, billing, token management |

The dashboard is NOT the product core.

**MCP local-first strategy:** V1 MCP prioritizes local and IDE agent workflows (local coding agents, IDE assistants, terminal agents). A hosted multi-tenant MCP control plane is NOT a V1 goal. The MCP server should reuse CLI-established auth state (e.g., `~/.debugbundle/auth.json`) when running locally so agents don't need separate login flows.

## 7. Primary User Flows

### Agent-Driven Installation Flow (Recommended)

```
User gives agent a ready-made prompt (from docs)
→ Agent runs: npm install / pip install / composer require
→ Agent runs: debugbundle setup
→ Agent reviews generated profile.json
→ Agent reads .agents/skills/debugbundle/SKILL.md (learns how to use DebugBundle)
→ Agent optionally enriches profile (critical paths, route ownership)
→ Agent updates AGENTS.md with DebugBundle instructions
→ Agent is now DebugBundle-aware: auto-checks incidents on bug reports
```

### Manual Installation Flow

```
Install SDK → Install CLI → debugbundle setup → Review profile
→ Give agent "Step 2" prompt (teaches agent to read .agents/skills/debugbundle/ skill)
→ Deploy to production
```

### Human Developer Flow

```
Deploy to production → Incident occurs
→ CLI fetches incidents → Developer/agent inspects bundle
→ Issue reproduced locally → Fix created
```

### AI Agent Flow

```
Incident occurs → Webhook fires → Agent calls API/CLI/MCP
→ Agent fetches debug bundle → Agent runs reproduction
→ Agent proposes fix → Agent opens PR → Human reviews and merges
```

### Local Analysis Flow (Free Tier)

```
User reports bug → Agent checks DebugBundle incidents
→ Agent fetches bundle → Agent runs `debugbundle analyze --local`
→ Analysis follows skill-layer recipes using agent’s LLM
→ Agent generates improvement/performance bundle locally
→ Agent proposes fix based on analysis
```

## 9. Non-Goals for V1

- Full dashboard / analytics UI
- Full session replay / video replay / heatmaps
- Distributed tracing UI
- Custom charting / query engines
- Enterprise RBAC / SSO / SCIM
- Multi-language SDKs beyond Node.js, browser, Python, and PHP
- Kafka / ClickHouse / Kubernetes
- Marketing email campaigns
- Complex permission matrices

---

## 10. Product Principles

1. Context over dashboards
2. Artifacts over raw logs
3. Resolution over monitoring
4. AI-native workflows
5. Developer-first UX
6. Bundle-oriented design (not generic observability)
7. Interface parity: API / CLI / MCP must expose the same capabilities
8. Everything available as API — anything a human can do should be possible through API

## 13. Pricing Model

See `/spec/tiers.md` for the finalized source-of-truth pricing model. Summary:

### Free Plan
- Unlimited projects, 1 member (owner only)
- 7-day bundle and raw event retention
- Failure bundles, CLI, API, MCP, basic webhooks, verification
- Local improvement/performance analysis via agent (user’s own LLM)
- Full SDK capture (all vanilla hooks + framework integrations)
- Always-on probes (ring buffer + error flush)
- No remote probe activation

### Solo Plan ($2.99/month)
- For independent developers and agent-driven projects.
- Unlimited projects, 1 member (solo only)
- 3 included capacity units
- Extra capacity units: +$0.99/unit/month
- 30-day bundle retention, 14-day raw event retention
- Remote probe activation included
- Configurable operational alerts
- Local/manual improvement bundles only (no cloud automation)
- Included and purchased capacity units expand the shared allowance bucket

### Team Plan ($19/month)
- Unlimited projects and unlimited project collaborators
- 15 included capacity units
- Extra capacity units: +$1.99/unit/month
- 90-day bundle retention, 30-day raw event retention
- Shared dashboards, project collaborator invites, Slack integration, priority support
- Higher operational limits and higher allowance per included or purchased capacity unit

### Enterprise (post-V1)
- Unlimited projects, SSO, SCIM, fine-grained RBAC, custom contracts

### Pricing Philosophy
- Allowance-capacity units as the primary pricing lever (each included or purchased capacity unit carries usage allowance)
- No volume pricing (bundles are rare high-value artifacts)
- No per-event billing
- Solo tiers stay cheap and approachable
- Collaboration and cloud automation value lives in Team

## 14. Cost Constraints

Initial hosted-launch cloud service costs must stay within an explicitly approved lean baseline. For the current allowlisted launch, the approved target baseline is roughly **$30/month** with an approval ceiling around **$35/month**; do not exceed that ceiling without explicit user approval. Services must remain reliable, performant, and agent-accessible (no aggressive bot-detection gates).

## 15. Success Metrics

- Time from incident to first useful bundle
- Time from incident to reproduction
- Time from incident to PR opened
- Bundle fetches per incident
- % incidents with successful reproduction artifact
- Alert-to-action latency
- Retention of CLI users

**Core outcome metric:** How much faster can a human or AI agent move from production failure to validated fix?

---

## 16. Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Privacy concerns | Strict default redaction, privacy docs, project-level controls |
| Building full observability | Stay bundle-focused, avoid dashboard sprawl |
| Infrastructure costs | Compact event model, retention limits, aggressive compression |
| Reproduction overpromises | Confidence scores, explicit limits, best-effort only |
| Building for humans only | Machine-readable CLI/API from day one, agent workflow as primary design constraint |
| Context window tax | Sophisticated context pruning to keep bundles within agent token limits |
