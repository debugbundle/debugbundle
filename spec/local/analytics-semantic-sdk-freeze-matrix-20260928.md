### Node strict manual tracking and outbox delivery — candidate, 2026-09-29

The isolated API is `createSemanticAnalyticsNodeDelivery(config: SemanticAnalyticsNodeDeliveryConfig): SemanticAnalyticsNodeDelivery`, exported by `@debugbundle/sdk-node`. Its configuration is `{projectId: string, writerToken: string, serviceName?: string, environment?: string, framework?: string|null, endpoint?: string, enabled?: boolean, requestTimeoutMs?: number, fetchImpl?: typeof fetch}`. It has `prepare(name: string, properties: Record<string, unknown>, options: SemanticAnalyticsNodePrepareOptions): Promise<AnalyticsPreparationResult>` and `deliver(records: readonly AnalyticsPreparedEvent[]): Promise<AnalyticsDeliveryResult>`. Additive `refreshCapability(): Promise<SemanticAnalyticsNodeStatus>` negotiates explicit authenticated authority before best-effort capture; `track(name, properties, options): void` finalizes a protected volatile record, and `flush(): Promise<void>` makes one bounded attempt. `getStatus(): SemanticAnalyticsNodeStatus` returns only local enablement, volatile queue count/bytes, in-flight state, last capability check state and a fixed last-failure reason; it is not current server authorization. `options` is `{eventRevision: number, operationId: string, eventId?: string, occurredAt?: string, measurements?: Record<string,{unit:string,value:string}>, traceId?: string|null, deployId?: string|null}`. This separate object permits analytics-only Node initialization without calling or resetting installed debug `init`; it does not alter `debugbundle.flush()` or claim automatic capture. `enabled` defaults to false. The credential must be `dbundle_anl_` and is never used as a project token or copied into a prepared record. The canonical endpoint default is `https://api.debugbundle.com`; explicitly configured HTTP(S) self-hosted bases are allowed after URL normalization without userinfo/query/fragment.

`prepare` is local and network-free. It admits only strict-privacy, nonfinancial `business_measurement` semantic events with a caller-supplied stable opaque `sha256:` operation reference and declared event revision. It checks event age (at most seven days), snapshots hostile properties/options through mandatory bounded sanitization without invoking getters, validates the V2 schema and returns immutable compact JSON bytes with the shared destination/content hash protocol. Omitted service name and environment now use `node-service` and `NODE_ENV` (or `development`), matching the debug SDK's defaults. The application must commit the record with its business change; an unavailable result has no effect on that transaction unless the application explicitly chooses one.

For a direct connected consumer, the application owns its durable prepared-record rows, calls `deliver` after commit, and removes only receipt-accepted indexes after transactionally recording the receipt. The candidate checks record schema, exact-byte SHA-256, destination/project, fixed expiry, future preparation, nonfinancial payload and current mandatory privacy protection before any network request. It checks a fresh authenticated `GET /v1/sdk/config` semantic capability on every call; the composed API currently advertises disabled capability, so production dispatch remains closed. With an enabled injected capability, it sends one 1–256 event, at-most-256-KiB POST to `/v1/analytics/deliver`, and returns only a validated matching indexed receipt. It owns no queue, cache, retry worker, file mode or second debug sender; concurrent calls return bounded `capacity_exceeded`, and one 1–60-second timeout covers negotiation and delivery. A local-file prepared record has no cloud acceptance until an explicit connected call. Browser relay, Node framework relay, and native bridge modes do not use this server credential or this API. Financial payloads return `unsupported` until billing-source authority and dedupe exist.

This is **partial Node SDK work**, not a frozen Node writer.
