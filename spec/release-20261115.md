Owner-authorised patch release scope and evidence index. Workflow links expose

## Scope and versions

Core 1.27.1 and site 1.10.3 contain the shared SDK documentation contract,
cross-surface checks, consistent setup examples, SDK guides and Rust launch post.
The organisation profile and all maintained SDK READMEs follow that pattern.
Requirements and applicability are in [the alignment record](sdk-documentation-alignment.md).

SDK documentation is distributed through independent patch releases: Node/Browser
3.2.3, Python/PHP/Ruby/WordPress/.NET 2.1.3, Java/Go/Android/React Native 3.1.3,
Swift 3.1.4 and Rust 1.0.1. These retain their public APIs and runtime behaviour;
package version metadata advances with their documentation. Dependency roots
publish before wrappers, with the normal exact-artifact and registry-consumer gates.

CLI 1.25.1, MCP/OpenClaw 1.25.0, shared JS packages and developer extensions retain
their published versions. No changed code or package content requires their release.
The independent OpenAI candidate and all consumer products remain outside this work.

## Deployment and acceptance

This change adds no application runtime behaviour, migration or infrastructure.
The usual trusted hosted-stack workflow pins qualified core/site SHAs, promotes
API/worker images before app/site assets and preserves the verified rollback pair.
Runtime code retains its behaviour while the root image version advances to
1.27.1. Deployment identities and served bytes are verified independently.
No paid-model generation, production synthetic events or consumer adoption is needed.

Before publication: strict SDK documentation checks, source review, core quality
gates, each SDK's required qualification and the site's tests/build/typecheck must pass.
After publication: independently verify package versions and public artifacts,
GitHub releases, live homepage/init examples, article/metadata/archive/sitemap,
SDK navigation, previous public routes, readiness and the deployed app identity.

Site 1.10.2 qualified the launch content; final pre-deploy review found current
release labels still naming the previous SDK patches. Site 1.10.3 aligns those
labels and native pins before production. A strict local manifest-to-guide check
now covers all thirteen surfaces in addition to the common setup-pattern checks.

The CocoaPods provider schedule was refreshed on 15 November: testing 2–6 November
and permanent read-only on 2 December 2026. Swift uses its existing immutable Git
and SPM release path; CocoaPods Trunk remains a separately selected channel.
