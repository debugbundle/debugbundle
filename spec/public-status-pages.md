# Public status pages

Owner-approved on 2026-10-08. Implementation and local acceptance are complete;
the owner authorized the release train on 2026-10-10. Core 1.16.1 is live, including the owner-approved controls follow-up.
Publication and deployment evidence is maintained in [the initial release record](public-status-release-20261010.md) and [the controls patch record](public-status-followup-release-20261010.md).

FR-AVC-07 extends FR-AVC-03/05/06 with one opt-in public page anchored to a project. The owner can choose a custom page title, explicitly include other projects owned by the same account, and explicitly select existing checks. Project and selected check names are retained. Newly created projects/checks remain private. There is no template system, subscription feature, or separate history page.

The public surface reuses the Health Status project's expandable rows, current status, check-weighted 30-day uptime, and UTC daily history bars. Public projection allows only the title, names, anonymous display keys, status, availability aggregates, and latest verified timestamps. URLs, service/environment labels, plans, errors, HTTP detail, incident references, logs/bundles, account data, and internal IDs are excluded at the server boundary. Ordinary authenticated routes remain protected and the monitor/incident lifecycle is unchanged.

AC-AVC-07 must verify owner-only publication, same-owner/same-account inclusion, explicit check selection, cross-project rejection, private-by-default behavior, stable share URLs, unpublishing, deletion, current ownership revalidation, strict output allowlists, no anonymous side effects, stale/paused/unmeasured coverage, retained outage history, count-weighted uptime, public rendering without auth, shared authenticated rendering regression, API/CLI/MCP parity, forward migration from the predecessor, checksum/idempotence, readiness fail-closed, and migration-before-runtime orchestration.

Design: reuse current semantic tokens, typography, spacing, shadcn primitives, keyboard/focus behavior, and responsive health rows. Add publication title, included-project/check selection, enable/save, copy/open, publication preview and the linked Powered by DebugBundle footer. Public states cover loading, empty, unavailable, stale, paused, unknown, operational and outage; no color-only meaning.

Owner-directed modal refinement (2026-10-09): a Public status page toolbar button immediately left of Create health check opens the existing generic form modal, with a scrollable body and fixed action footer. Use the shared searchable multi-select menu for Other projects and one check selector per included project, with a fixed anchor, compact selection summaries and pagination inside each menu. Search only filters loaded choices and never clears selections; load more when a choice is not yet available. Use the existing enable switch and action buttons. Show the published URL in a labelled read-only input with a copy icon on the right and an open-page action. Clipboard failure selects the input for manual copying. Settings load only on opening; closing discards unsaved edits and reopening reads saved settings. Saved preview opens in a scrollable dialog and returns focus to its button. Closing selectors or preview keeps settings open; closing settings returns focus to the toolbar and ignores pending responses. Empty, disabled, loading, failed-save and failed-preview states preserve the established disclosure and publication controls.

Owner-directed device theme, branding and tooltip refinement (2026-10-10): public pages use the device light/dark preference before React mounts and update while open, independently of the dashboard preference. Private routes retain their normal theme controls/storage. Retain the single-line, underlined Powered by DebugBundle link. Place only the existing small brand mark above it in a separate accessible link, with increased spacing using current tokens. Daily status tooltips use the existing Radix disable-hoverable-content option at the shared strip to avoid blocking narrow neighboring days; project/check blocks in authenticated Health Status, anonymous status and saved preview use the same behavior. Keep keyboard descriptions, focus and Escape dismissal, and preserve ordinary tooltips.

Owner-directed controls follow-up (2026-10-10, released in core 1.16.1): the enable switch saves immediately. First enable creates and publishes a new page with its validated title and explicit selections. Existing pages toggle using the saved configuration and retain other form edits until Save status settings. The switch explains the distinction and saving state; failures restore the saved switch state without losing drafts. Existing configurations without saved checks require saving selected checks before enabling. The read-only copy input appears while enabling, with copying disabled until a URL exists. Open status page requires successful publication, and a live link remains until disabling succeeds. Rename the preview action to Preview status page while retaining saved-preview semantics. Opening it focuses its heading rather than the first history block, preserving keyboard day details and focus return without an automatic tooltip. These follow-up changes shipped with explicit owner authorization; the controls patch record contains exact source and live verification evidence.

Deployment defaults to the existing app `/status/<id>` path. Optional matching API/build URL configuration supports a dedicated root status host; DNS/TLS/static alias setup is an operator deployment step. Hosted public throttling trusts only the appended last IP behind its loopback-only Caddy binding; direct/self-host defaults do not trust forwarded IPs. The normal authenticated flow remains independent.
