# Agent distribution ledger

This is the maintained inventory for first-party developer agent packages that bundle the local DebugBundle MCP server and a workflow skill. It complements the [MCP ecosystem release manifest](../apps/mcp/ecosystem-release-manifest.json), which tracks the npm server, MCP Registry, Smithery, ClawHub, OpenClaw, and downstream discovery. That pipeline does not publish Codex, Claude Code, or Gemini CLI packages. The hosted, read-only [OpenAI plugin](../apps/mcp/openai/release-manifest.json) has its own release gate.

## When a package changes

1. Review an MCP npm release against each pinned version. A new `@debugbundle/mcp` version does not silently change any of these packages. If a package should adopt it, publish and smoke-test that exact npm version first.
2. For a changed package manifest, MCP pin, bundled skill, or behavior, bump that package's own version, update its changelog, keep shared skill guidance in sync, and run its contract and native-client smoke checks. Update this ledger's version and pin from the candidate source in the same change. A documentation-only edit outside a package does not require republishing the package.
3. Publish Codex and Claude Code changes through their reviewed core marketplace source. For Gemini, publish the validated five-file package to the standalone repository's default branch, create a matching version tag, publish a GitHub Release on that tag with the deterministic ZIP, and run `make gemini-extension-verify-public`. A tag alone does not create a GitHub Release. The core source remains authoritative; do not edit the public copy independently.
4. Verify a fresh install and update from the exact public source, then update the public setup guide and this evidence table. Record gallery or third-party directory visibility only after checking it directly. An accepted package or tag alone is not evidence of indexing.

Gemini Git installs compare the public branch commit for updates; users run `gemini extensions update debugbundle-gemini` and restart Gemini. Its gallery crawls tagged public repositories and lists extensions that pass validation. There is no separate manual gallery submission. See [Gemini's release guide](https://geminicli.com/docs/extensions/releasing/) and [DebugBundle's Gemini setup guide](https://debugbundle.com/docs/mcp/gemini/).
