# Public status publication

Applies to FR-AVC-07 / AC-AVC-07 in addition to SEC-01 through SEC-26.

The enable switch saves immediately. For a new page, first enable validates and saves the current title and explicit check selections to create and publish it. For an existing page, save visibility using its saved configuration and preserve unsaved form edits; title/project/check changes require Save status settings. Explain these semantics beside the switch. Disable competing controls while saving, restore the saved switch state on failure, preserve drafts and ignore late responses after closing. An existing configuration with no saved checks must save selected checks before enabling. Reveal the read-only link field while enabling, with copying disabled until a URL exists; only offer Open status page after publication succeeds. Retain a live link until disabling succeeds. Label the preview action Preview status page; initially focus its heading rather than a history block so no tooltip opens automatically. Preserve deliberate keyboard access to day details and focus return.

Publication is a separate owner-controlled read projection. Do not weaken existing authenticated availability routes or reuse SDK write tokens as public read credentials. One anchor project owns its publication metadata and random 96-bit URL identifier. A URL is public, not a secret or authorization token.

Persist explicit project/check selections atomically. Revalidate the anchor, every included project's current organization/owner, undeleted check membership and existing plan execution eligibility on every public read. Soft deletion, hard deletion, unpublishing and reassignment fail closed. New checks are never automatically included. Invalid selections cannot partially replace the published page.

Lock selected projects, including the anchor, in a consistent global order before replacement so simultaneous pages with reciprocal selections cannot deadlock. Health check choice refreshes preserve unsaved title/selection edits and only discard deleted selections when the complete option list proves absence. Backgrounded public pages revalidate when visible again before showing the old result.

Owner controls use the shared searchable multi-select menu, with the anchor fixed and pagination available inside project/check menus. Filtering loaded choices must never change selection membership or discard unloaded IDs. Newly included projects start with no selected checks; excluding a project removes only its selections. At the 50-project, 50-check-per-project and 500-total-check bounds, selected entries remain removable. Open settings through a Public status page toolbar button immediately left of Create health check. Reuse the generic form modal with a scrollable body and fixed action footer; do not load settings until it opens. Closing discards unsaved edits and reopening loads saved settings. Return focus to the toolbar trigger on close and ignore async results after unmount. Render the published URL in a labelled read-only input with an inline copy icon on the right, plus the existing open-page action; clipboard failures select the input for manual copying. Saved preview uses existing dialog primitives with a scrollable body and focus return to its preview button. Closing a selector or preview must leave the settings modal open.

Project/check names and the title are intentionally published and must be described as such in owner controls. Sanitize the new public title before persistence and apply mandatory SEC-23a sanitization to all display text and a strict server output schema. Allow only title, names, anonymous positional keys, status, uptime, latest verified timestamps and 30 daily availability aggregates. Never serialize internal IDs, URLs, service/environment labels, errors/status codes/timing diagnostics, incident references, account/plan data, bundles, logs or credentials. Retained incident references may inform outage impact inside the projector but never cross its boundary.

Public pages follow the device color scheme at startup and while mounted, independently of stored dashboard preferences. Keep private theme preferences and controls unchanged; anonymous rendering must not require dashboard storage access. Keep the underlined Powered by DebugBundle attribution on one line. Place the existing small brand mark above it in a separate link with an accessible DebugBundle label and a generous gap using the existing spacing scale. Daily status tooltip content is plain text: disable its hover corridor at the shared strip so adjacent days open on the first pointer movement. Preserve keyboard descriptions/dismissal and ordinary hoverable tooltips.

Use the existing Health Status calculations for history and count-weighted uptime. Derive freshness only from verified daily rollups, not raw internal-error attempts. Beyond three effective check intervals show unknown. Current project status uses failing, then unknown, then paused, then operational precedence so incomplete coverage cannot hide behind a passing check. This conservative public aggregation does not change existing authenticated aggregation or stored monitor state.

Public reads never probe, queue, create incidents, send notifications or write customer state. Rate-limit anonymous reads at 120 per IP/minute, outside member management buckets; limiter failure is unavailable. Public responses are no-store and all missing/disabled IDs share a generic 404. Deployment proxies must honor no-store. Do not expose a page directory or an enumeration API.

Publication changes require project owner authorization and normal CSRF/member-token protections. Audit success and failures using bounded counts/flags/reasons, without titles, names or check selections. Collaborators can read only the published title/link, not other-project configuration or unpublished preview.

A dedicated status origin may have anonymous public GET CORS only. Never add it to the credentialed management allowlist. Dedicated root-host routing must avoid private providers even for unknown paths; public visits must not initialize app dogfooding/session analytics. Default same-app `/status/<id>` links remain supported without extra infrastructure.

Additive tables use ordered checksummed migrations and readiness gates. Bootstrap is only for empty schemas. Deploy migration before API/worker activation; do not rewrite existing availability tables or trigger backfills/checks.

The opted-in local mock preview may simulate publication in memory using the same strict schemas and aggregate projector. Project/check IDs must be valid UUIDs, public links must use the current loopback preview origin, and restart must reset publications. Mock management must not proxy or mutate real services, and mock public reads must not execute checks. This is UI review evidence, not real database/auth/migration evidence; SEC-10 development-only build isolation still applies.

By default use the socket peer IP for public throttling. `PUBLIC_STATUS_TRUST_PROXY=true` may use only the last valid IP from a bounded X-Forwarded-For header, and only when the API is reachable exclusively through a trusted proxy that appends the actual peer. Hosted API ports must remain loopback-only. Never enable this on a directly reachable API or trust earlier caller-supplied hops. This setting affects only public-status throttling, not authentication or existing route authority.
